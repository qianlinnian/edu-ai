## 本周完成内容（代码细节）

### 1) 练习评判 + 掌握度动态更新

- 主要文件：`backend/education/exercise_engine.py`
- 核心能力：
- `evaluate_attempt(...)`：统一支持“题库题 / 生成题”两种来源，读取参考答案并完成自动评判。
- `_judge_answer(...)`：按题型区分评判策略：
- `choice` / `fill_blank`：标准化后严格相等判定。
- `short_answer` / `coding`：基于 token overlap 的轻量相似度评分（阈值 0.6 认为达标），输出 `is_correct + score_ratio`。
- `create_attempt_and_update_mastery(...)`：一次提交完成“作答入库 + 掌握度更新”：
- 作答入库：写 `exercise_attempts`。
- 掌握度更新：写 `student_knowledge_mastery`，维护 `attempt_count/correct_count/last_assessed_at`。
- 掌握度更新策略：EMA 平滑（`0.7*历史 + 0.3*本次结果`），避免一次作答导致掌握度大幅波动。

### 2) 针对性出题（题库优先，生成兜底）

- 主要文件：`backend/education/exercise_engine.py`
- `generate_targeted_exercises(...)`：
- 优先从 `exercise_pool` 按课程、题型、难度（±1）与知识点交集筛选。
- 不足数量时写入 `generated_exercises` 作为兜底占位题，保证接口可用以支撑联调与演示。

### 3) 学情分析引擎：掌握度、薄弱点、班级聚合报告

- 主要文件：`backend/education/analytics_engine.py`
- `student_mastery_overview(...)`：
- join `knowledge_units` + `student_knowledge_mastery`，输出学生在课程内的知识点掌握度概览。
- `weak_points(...)`：
- 筛选 `mastery_score < threshold`（默认 0.4）的薄弱点列表，支持阈值可调。
- `class_report(...)`：
- 聚合每个知识点的：平均掌握度、学生数、风险学生数（`mastery_score < 0.4`）。
- 输出 `overall_avg_mastery` 与 `by_knowledge_unit`，方便前端直接画图/排行。

### 4) 预警规则：薄弱知识点预警生成（去重）

- 主要文件：`backend/education/analytics_engine.py`
- `refresh_learning_alerts(...)`：
- 基于薄弱点批量生成 `learning_alerts`（本周聚焦 `knowledge_weak`）。
- 去重策略：对“未解决 + 同课程 + 同学生 + 同知识点”的预警不重复创建，避免刷新时刷爆预警表。
- 严重度：`mastery_score < 0.25 => high`，否则 `medium`。

### 5) API 路由接入（替换模拟逻辑，打通闭环）

- 主要文件：`backend/api/routes/exercises.py`
- `POST /api/v1/exercises/generate`：接入 `generate_targeted_exercises(...)` 返回真实题目列表（题库/生成两种来源均可返回）。
- `POST /api/v1/exercises/attempt`：接入 `create_attempt_and_update_mastery(...)`，提交后立即更新掌握度；随后刷新该学生在课程内的薄弱预警。

- 主要文件：`backend/api/routes/analytics.py`
- `GET /api/v1/analytics/student/{student_id}/mastery`：接入 `student_mastery_overview(...)`。
- `GET /api/v1/analytics/student/{student_id}/weak-points`：接入 `weak_points(...)`。
- `GET /api/v1/analytics/course/{course_id}/class-report`：接入 `class_report(...)`。
- `POST /api/v1/analytics/course/{course_id}/refresh-alerts`：新增手动刷新预警入口，便于联调/演示与后续任务调度接入。

### 6) 分支同步与集成

## 验证与自测方式（Docker 已跑通场景）

- 依赖启动：`docker compose up -d`
- API 启动：`uvicorn main:app --reload --port 8000`（在 `backend/` 下）
- 文档入口：`http://localhost:8000/docs`
- 最小闭环点测顺序：
1. `POST /api/v1/auth/register` + `POST /api/v1/auth/login` 获取 token，在 Swagger 右上角 `Authorize`
2. `POST /api/v1/exercises/generate`（传 `course_id` + `knowledge_point_ids`）
3. `POST /api/v1/exercises/attempt`（传 `exercise_id` 或 `generated_exercise_id` + `student_answer`）
4. `GET /api/v1/analytics/student/{student_id}/mastery`（验证掌握度变化）
5. `GET /api/v1/analytics/alerts`（验证预警生成）
6. `GET /api/v1/analytics/course/{course_id}/class-report`（验证班级聚合）

## 风险与待办

- 数据迁移：当前仓库缺少 Alembic `versions` 版本文件，首次运行环境可能需要补迁移或临时建表策略。
- 自动化测试：缺少 `pytest` 冒烟测试；当前主要依赖 Swagger 手工点测，回归成本偏高。
- Embedding/RAG：文档解析、向量入库与检索链路仍需补齐/加强（本周聚焦闭环核心业务）。
